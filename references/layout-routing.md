# Layout and routing decisions

## Check real use before committing placement
- Establish the actual product/application from project evidence. List normal installation, cable connection, programming/recovery, operation, shutdown and service actions. Check all connected plugs/cable exits together, including mating bodies, bends, strain relief, unplugging grip and screwdriver access; footprint clearance alone is insufficient.
- Trace battery-only, USB-only, both-supplies and switch-OFF states from the actual schematic/netlist. Identify rails that remain energized, backfeed paths and motor default states. A label such as POWER/OFF must agree with actual behavior. Do not assume firmware guarantees a safe output or that disabling a regulator disconnects the battery.
- Prioritize user-facing names, polarity, voltage, signal order and motor/port numbering over component reference labels on visible silk. Check that labels remain useful with cables installed and can be read in the normal mounting orientation. Identify identical-looking incompatible connectors and choose appropriate keying, placement or explicit markings without changing established pinouts casually.
- For controls and changes to their neighbors, apply [control access](control-access.md). Establish primary operating controls versus recovery/service controls from use scenarios. Reserve actuator travel and human access as placement constraints before placing surrounding components; recheck after connector, model, mounting or enclosure changes.
- Preserve agreed board outline, holes and connector anchors. If an anchor conflicts with verified use, document the conflict and develop a reviewable alternative before changing the agreed interface. Treat missing plug/enclosure dimensions as unverified, not a passed fit check.

## Review hand assembly, inspection and rework
- Identify what is factory assembled, hand soldered and installed later. Reconcile the actual BOM/placement exclusions with project notes; an informal `hand` flag is not proof the assembly export excludes a part. Preserve part choices while resolving contradictions.
- Walk through placement, tacking, completing joints, inspection, cleaning and component replacement with the intended iron tip, tweezers, hot air/preheater and board holder. Check each joint's access angle after neighboring/tall components are installed. Reserve usable tool space, not only electrical clearance; do not invent a universal soldering gap.
- For power tabs, ground pads and large pours, assess how heat reaches the joint and what copper carries load current. Choose direct connections or thermal relief geometry jointly with electrical/thermal requirements and the actual assembly process. Do not blindly add reliefs for easy soldering or solid pours for current capacity. Exposed pads and solder-wicking vias need a defined process that can be inspected.
- Treat specified allowed component populations per side as project constraints; verify actual mounted references after editing. Through-hole leads and copper are distinct from mounted packages. Do not generalize one project’s underside policy to other boards.
- Plan assembly order and support for both sides so previously installed parts are not damaged or remelted and tall connectors do not block tool access. Include polarity/pin-1 marks visible during assembly, orientation drawings that distinguish top/bottom, and BOM references readable at the bench.
- Provide accessible power/ground and relevant test points for unpowered shorts, staged power-up and fault isolation; prefer hands-off ring test points or coaxial probe sockets for live/high-power measurements to prevent probe slips. Check probe slips and access with cables fitted. Ensure joints that require inspection are actually visible or name the inspection method needed, and plan hand-solder touch-up for heat-sinking castellated module pads (e.g. ESP32) that often under-wet in reflow.
- For review/handoff, record each relevant human-use or assembly finding as action/scenario → evidence → change needed → verification state. Simulated perspectives from one assistant are not a test with real users or a successful soldering trial. Distinguish layout review, fixture/plug fit and physical assembly validation.

## Before routing
- Confirm outline, mounting datums, plated/non-plated holes, slots, tolerances, connector mating envelope and maximum component heights. Lock agreed mechanical anchors. Check actual 3D body projections and insertion/tool envelopes against every mounting position; a hole’s copper ring or courtyard is not the fastener envelope. Record assumed hardware dimensions when the actual hardware is unavailable. Check screw heads/washers, enclosure standoffs and underside components as well as hole centers.
- Choose layer count/stackup against return continuity, routing density, impedance, heat, EMC and cost. Obtain fab limits for spacing, copper-to-edge, annular ring, drills, mask and slots. Put relevant constraints into board settings/net classes/custom rules; inspect rule application rather than only the rule text.
- Verify footprint dimensions, pad numbering, exposed-pad connection, pin 1, solder-mask/paste apertures and courtyard against the actual package. Confirm connector front/rear mating view; a matching 3D model does not establish pad correctness. Keep custom libraries portable with the project.

## Place functional blocks
- Build a floorplan from functional connectivity and current flow: power entry/protection, conversion, switching/load output, control and sensitive measurement. Mark fixed anchors, keepouts, critical nets and routing channels. For a substantial redesign with competing constraints, compare feasible arrangements before detailed routing.
- Rotate and position components using actual connected pads and package pinout, not symbol appearance. Keep associated passives with their functional circuit; reserve escape space at fine-pitch packages. Check congested channels early and move blocks while placement is still inexpensive.
- Trace operating-state current loops on the schematic before placement. Place switchers/drivers with the exact manufacturer's recommended hot-loop, gate, bootstrap and sense geometry; place high-di/dt return paths on an adjacent inner layer rather than the opposite outer layer so loop area does not span the full board thickness. Do not shrink all distances indiscriminately at the expense of isolation or thermal needs.
- Place decoupling for a short supply-pin → capacitor → return loop; assess via placement and reference-plane continuity. A capacitor near an IC body with a long electrical loop is ineffective placement.
- Keep sensitive feedback, references, oscillators and analog inputs away from switch nodes and noisy magnetics. Use Kelvin sensing at the specified point; avoid shared high-current impedance in measurement returns.
- Reserve RF keepouts, test/programming access, fixture access, rework space and thermal copper before filling the board. Follow assembly constraints for edge parts and heavy/tall components.

## Route with the return path
- Define applicable per-net constraints before routing: width/clearance, current/drop/thermal assumptions, reference layer, impedance, length/skew and allowed layer transitions. Choose routing order by sensitivity and physical constraint; there is no universal rule that every power net must precede every signal.
- Use interactive routing and local shove/walk-around where supported, checking the displaced traces afterward. For automated/scripted routing, verify pad-to-pad connectivity, clearance and references after each meaningful pass. A ratsnest line or drawn graphic is not routed copper. If available tools cannot finish routing, report partial routing and the exact remaining nets rather than implying completion.
- Route coherent corridors with suitable pad entry and practical bends; avoid unnecessary detours, stubs and repeated layer changes. Select grids for the footprints and geometry. Cross unavoidable adjacent-layer traces perpendicularly to reduce crosstalk, and use smooth or mitered bends (never sharp 90° corners) plus ground pours/via fences where high-frequency impedance or isolation matters. Do not impose decorative symmetry, universal 45-degree rules or minimum via count at the expense of electrical constraints.
- Route critical power/gate/sense, clocks and constrained interfaces first; then general signals. Inspect shortest current loops and uninterrupted reference paths, not only shortest trace length or ratsnest count.
- Keep fast signals over a continuous suitable reference. Avoid plane splits, slots and via antipad barriers below them. When changing layers, design a nearby return transition appropriate to the reference planes; a ground via cannot stitch two unrelated power references.
- Prefer floorplanning that separates noisy and sensitive currents without arbitrarily splitting ground planes. Follow the particular device's analog/digital ground connection requirements. Ground pours, star grounds and stitching via grids are not universal cures.
- For differential pairs, preserve reference, coupling and symmetry through pads/vias/connectors as required by the interface. Tune only to an established timing budget; unnecessary meanders add coupling and loss. Check intra-pair skew and discontinuities, not just total pair length.
- Keep high-dv/dt copper compact and away from victims, while providing suitable current and thermal area elsewhere. Check clearance to adjacent layers and component bodies. Ensure thermal relief choices do not create current bottlenecks or assembly problems.
- Use actual copper/via/connector geometry in power calculations. Do not place more vias simply to imply a current rating. For thermal/exposed-pad vias, coordinate paste, tenting/filling and solder-wicking control with the assembler.

## Iterate placement and routing
If a critical path needs repeated vias, a long return detour, a narrow power neck or dense crossings, revisit placement, orientation, layer assignment or escape strategy before adding more routing. Do not swap connector pinouts or remap device pins without verifying that the change is allowed and updating the authoritative schematic/firmware as required by scope.

For an optimization request, compare the affected nets before/after: critical loop geometry, actual trace length and via count, bottleneck width, reference continuity, clearance and mechanical access. Use applicable targets rather than a single cosmetic score; fewer vias or shorter total length alone does not prove improvement. Keep intermediate checkpoints so an unsuccessful optimization can be reverted without losing unrelated work.

## Inspect final geometry
Refill zones, then inspect both sides and relevant inner layers: actual return continuity, isolated copper, thermal spokes, neckdowns, pad entry, copper-to-edge and accidental stubs. Inspect mask/silk, pin/polarity labels, human-readable connector labels and test points. Use 2D plus 3D views; neither replaces dimension or electrical checks. If viewing tools are unavailable, report the visual/fit check as pending.

Highlight critical nets and verify each intended pad connection, including zone-connected pads and thermal spokes after refill. Inspect differential/escape routing and crowded areas at useful zoom. Confirm zero unintended unconnected items from the current DRC report; justify any deliberate exceptions individually.

For production export and exported-layer inspection, follow pcb-fab-prep rather than duplicating its release procedure here.

## Dense-board practice (from real boards)
- Mounting holes: plated copper ring on both outer layers tied to GND with a symmetric ring of stitching vias (e.g. 8 vias at 45° steps), with spacing checked against copper-to-edge; move parts, not holes. Never leave a bare Edge.Cuts circle unless the user says so.
- Placement probes: for through-hole pads test every layer the pad occupies, including SMD parts on the opposite side; an F.Cu-only probe misses bottom-side collisions. Keep body (F.Fab), courtyard, pads and height as separate checks; a courtyard overlap is not proof of body collision, and do not delete courtyards or exclude DRC to pass.
- Subset changes: after a footprint swap, re-place only the changed parts locally rather than rerunning the full search; probe locally, run full DRC once per batch.
- Solderability of exposed copper: open mask on reinforcement tracks only where an iron can reach (body envelope plus ~0.7 mm iron clearance; roughly >=0.8 mm wide and >=1.5 mm long), otherwise the opening adds nothing.
- External STEP models: verify rotation and Z seating separately from the footprint; a model with its origin at mid-height sinks through the board. Never substitute a similarly named model.
- Autorouting (FreeRouting, headless `java -Djava.awt.headless=true`): export the DSN only from a fresh unrouted board (old wiring becomes fixed and hurts); set GND pads and mounting-ring pads to net 0 in the DSN copy and let the planes tie them, route leftover GND afterwards; use the real pad shape (circle/oval) for snapping or tracks dangle; tent vias to avoid silk-over-copper. Remaining 1–5 unrouted nets move with tiny placement or rotation changes (rotate the dense IC 270°, widen the escape tab) rather than router flags, so loop small offsets as a script and stop at the first 0. Router clearance equals the DRC rule: rounding leaves 1–8 µm misses, so nudge/narrow afterwards. Never keep backups or helper scripts in the router work folder (`prepare` may delete it). Importing an SES moves footprints to the SES pose, so re-apply any placement tweak. A GUI open on the project rewrites `.kicad_pro` and reverts rules; close it or reassert rules before DRC.
- Blocked corridor: crop the search to the smallest box holding the endpoints and real blockers (a 7.5×4.75 mm A* solved in ~2 s after whole-board search failed); rip up only an explicit soft-net whitelist and reject any proposal that raises non-GND unrouted count.
- Bottom-side parts: `Flip(LEFT_RIGHT)` then orientation +180. 3D model: set `(attr smd)`/`through_hole` or the viewer hides it; fit rotation/offset by matching STEP vertices to pads, do not copy from another part.
- Scripted pcbnew edits: cache coordinates/UUIDs/shapes before `Add`/`Remove`, since SWIG proxies can become invalid; save and reload between phases. For batch track widening, roll back only the UUIDs named in new DRC clearance errors.
